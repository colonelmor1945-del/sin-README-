# GTA 6 Money Lab

Make money. Dominate Vice City.

An independent AI intelligence platform for GTA 6 players. Plan money
strategies, compare missions by their real hourly rate, and track asset payback
periods.

> **GTA 6 Money Lab is an independent fan-made platform and is not affiliated
> with, endorsed by, or associated with Rockstar Games or Take-Two Interactive.**
> No Rockstar artwork, logos, screenshots or map assets are used. The map is an
> abstract shape drawn in code; the photography is licensed placeholder imagery.

## Quick start

```bash
npm install
npm run dev
```

Open http://localhost:3000. **No API key is required.** Without one the app runs
on a deterministic local analyst that uses the same formulas the model is asked
to reason over, so every screen works offline.

To use Claude, copy `.env.example` to `.env.local` and set `ANTHROPIC_API_KEY`.
Settings shows which provider is live.

## The one product rule

GTA 6 has not shipped a stable public economy. Everything currently in the app
is placeholder data authored for this prototype, and **nothing is verified**.

Every game figure carries a provenance label that travels with it wherever it
appears:

| Label | Meaning |
|---|---|
| Verified | Confirmed against an official Rockstar source |
| Community data | Player-reported, cross-checked across two or more sources |
| Estimated | Derived by our own formulas from other data points |
| AI projection | Generated by the model. Lowest confidence |

The system prompt enforces the same rule on the model: it may not invent a
mission, asset or price that is not in the dataset it was handed, and it must
name the confidence level when it quotes a number. `src/lib/provenance.ts` is
the single source of truth, and `<ProvenanceTag>` is the only component that
renders it. Electric blue is reserved for AI projection and appears nowhere
else in the product.

## Architecture

### Analytical core

`src/lib/calc.ts` holds every formula as a pure function: risk-adjusted hourly
rates, payback periods, level gating, goal projection, strategy filtering. It
has no I/O and no framework.

This matters more than it looks. When the assistant claims a payback period it
is quoting one of these functions rather than inventing a number, which is what
makes the advice checkable. The Money Calculator runs the same functions with
no AI involved at all.

The headline metric is **risk-adjusted hourly**: payout minus the expected cost
of failed runs at that difficulty, divided across the crew the mission needs.
Every list that claims to sort by money per hour sorts on that figure, not on
raw payout, so the order is one the reader can verify.

### AI layer

```
src/lib/ai/
  provider.ts    the AiProvider interface. Nothing else imports a vendor SDK
  claude.ts      Claude Opus 5
  heuristic.ts   deterministic fallback, no key needed
  prompts.ts     frozen system prompt + dataset digest (the cached prefix)
  schemas.ts     Zod schemas for structured output
  index.ts       provider selection, the only file that picks a vendor
```

Swapping vendors means adding one file that satisfies `AiProvider` and changing
one branch in `index.ts`.

Notes on the Claude requests:

- `thinking` is omitted, which runs adaptive thinking on Opus 5.
- The system prompt plus the dataset digest is a frozen prefix carrying the
  cache breakpoint. Only the player profile and the question vary, so the cache
  hits across every user.
- Plans and creator packages use structured output (`output_format` with the
  beta Zod helper), so the UI never parses prose.
- Chat streams, so a long answer cannot hit an HTTP timeout.
- `stop_reason === "refusal"` is handled and surfaced as a plain message.

Two upgrades are gated on a newer `@anthropic-ai/sdk` than the pinned 0.71:
server-side refusal fallbacks (`fallbacks: "default"`) and `stop_details.category`
for a more specific refusal message.

### Data and persistence

`src/lib/db/schema.sql` is the production PostgreSQL schema: users, profiles,
assets and their price time series, missions, map locations, money plans and
steps, AI conversations and messages with token accounting, Lab Credits with an
append-only ledger, payments with an append-only event log, crypto payments,
support contributions, news items, and an audit log.

`src/lib/db/store.ts` defines the repository interface and ships an in-memory
development adapter that mirrors the schema one to one. Phase 1 runs on it so
the product is demonstrable without provisioning Postgres. The Postgres adapter
is a straight translation with no changes to calling code.

### Security posture

- Authorisation is always server-side, read from the store, never from the
  request. The client is told what it may show, never what it may do.
- Passwords are hashed with scrypt (N=2^15, r=8), a random per-password salt,
  and the cost parameters stored alongside the hash so they can be raised later
  without invalidating existing passwords. Verification is constant-time.
- The session cookie holds an opaque random token; the store keeps only its
  SHA-256. A leaked database cannot be replayed as a live session, and since
  nothing about the user, tier or role travels in the cookie, a tampered cookie
  can only ever be invalid, never privileged.
- Sign-in returns the same message and burns comparable time whether the email
  exists or not, so account existence cannot be probed by wording or by timing.
  Sign-in and sign-up are rate limited per client IP, not per email, because the
  attacker controls the email field.
- `src/middleware.ts` bounces anonymous traffic off protected routes, but it is
  a filter and not the authorisation check: the token is validated against the
  store in `requireSession()`, which every protected page and route calls.
- Sign out is a form POST, so it cannot be triggered by a prefetch or a crawler.
- Every API route validates its body with Zod before touching anything.
- Rate limiting sits in front of every AI route, separate from the per-tier
  quota, and runs before the model call so abuse costs nothing.
- Credits are debited before the model call and refunded automatically if it
  fails.
- Webhooks verify the signature over the raw request bytes with a constant-time
  comparison and a timestamp tolerance. There is no debug bypass. Status changes
  pass through a transition guard so a retried or out-of-order event cannot
  demote a confirmed payment. Entitlements are granted only on the confirmed
  transition, and only from the webhook.
- No table stores private keys, seed phrases or plaintext passwords.

## What is built and what is not

| Area | State |
|---|---|
| Landing page | Done |
| Launch countdown, with its own provenance label | Done |
| Dashboard, objective, next move, best purchase | Done |
| AI assistant, streaming, profile-aware | Done |
| Money plan generator, structured output, progress tracking | Done |
| Money calculator, four calculators, no AI | Done |
| Mission intelligence, list plus detail, five sorts | Done |
| Economy tracker, payback ranking, sparklines | Done |
| Interactive map, six filterable layers | Done |
| Creator Lab | Done |
| Intel feed with editorial provenance rules | Done |
| Fund the Lab page and legal page | Done |
| Admin panel | Reads live content and service state |
| Tier gating and Lab Credits | Enforced server-side |
| Postgres | Schema written, adapter not wired |
| Authentication | **Done.** Email plus password, scrypt hashing, opaque server-side sessions |
| Payments | Provider interface, status machine and webhook verification written. No processor configured, so `createIntent` throws rather than pretending |
| Analytics and business metrics | Admin shows these as unavailable rather than as zero |

Anything unconfigured falls back to a safe local behaviour or says so plainly.
Nothing fakes a working integration.

In development, Settings has a **Switch for review** control on each plan so the
Pro and Elite surfaces are reviewable before payments are wired. It refuses to
run when `NODE_ENV` is production.

## Design system

Locked dark theme. One accent, applied everywhere: neon pink for every CTA,
link, active nav item and focus ring. Violet-tinted neutrals are surfaces, not
an accent. Electric blue is reserved for the AI projection marker. Green and red
are financial semantics in the economy tracker only.

Radius rule: interactive controls are full pill, panels are 14px, inputs and
cells are 10px. Numbers are set in Geist Mono with tabular figures.

Motion is scroll-reveal on landing sections and hover states on controls, all
gated behind `prefers-reduced-motion`.

## Roadmap

**Phase 2.** Postgres adapter, Google sign-in alongside the existing email and
password, email verification and password reset, persisted conversations,
subscriptions.

**Phase 3.** Stripe subscriptions, credit packs, BTCPay contributions, the
supporter badge system.

**Phase 4.** Live economy sampling into `asset_prices`, alerts, an editor UI for
missions, assets, map locations and the intel feed, and community submissions
with a verification queue that can finally promote records to Verified.

**Phase 5, other platforms.** The target is Xbox, PlayStation, Play Store and
the App Store. The realistic order, cheapest first:

1. **Installable web app.** Add a manifest and a service worker. This already
   works on every one of those devices through the browser and costs days, not
   months.
2. **Play Store and App Store.** React Native via Expo, reusing `src/lib`
   unchanged. That directory is deliberately pure TypeScript with no React and
   no framework imports, which is what makes a native client a new interface
   over the same engine rather than a rewrite. Budget for store review, an
   account deletion flow, and Apple taking a cut of subscriptions bought in
   app.
3. **Xbox and PlayStation.** The hardest, and worth being blunt about: console
   storefronts do not accept companion utilities from unaffiliated developers
   as a matter of routine. Both require a registered developer programme, and a
   third-party app trading on another publisher key intellectual property is
   the kind of thing platform certification rejects. The honest path there runs
   through Rockstar, not around them. Xbox is the softer target because Edge on
   console can open the installable web app from step 1 today.

## Legal

Lab Credits are platform usage credits for premium AI actions. They are not
cryptocurrency, not an investment product, not a transferable financial asset
and not a security.

Contributions through Fund the Lab are voluntary, fund development and
infrastructure, and do not represent an investment or ownership interest. They
are recorded with amount, timestamp and provider reference so they can be
reported as income. The system does not offer anonymity and does not obscure who
receives funds.

Nothing here is financial advice. Everything concerns fictional in-game currency
in a video game.
